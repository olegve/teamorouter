# Визуализация затрат TeamoRouter

Документ описывает, **что и как** плагин показывает по затратам на модели
TeamoRouter: дневные и месячные суммы, стоимость запроса, стоимость хода и
итог за сессию. Контекст задачи — в [AGENTS.md](AGENTS.md); общий план — в
[plan.md](plan.md); исследование API — в [research.md](research.md).

## Цель

- Показывать **фактические затраты за сегодня и за текущий месяц**.
- Сразу после ответа модели показывать **оценку стоимости запроса**.
- Показывать **стоимость завершённого хода** (сумма запросов внутри хода).
- Показывать **итог за сессию**.
- Не трогать других провайдеров и не менять ядро DSH.
- Явно помечать оценку знаком `≈`, чтобы её не путали с фактическим списанием.

## Источники данных

### Usage из сессии

Для каждого assistant-сообщения в логе сессии сохраняется:

- `message.source.provider` и `message.source.model`;
- `usage`: `inputTokens`, `outputTokens`, `totalTokens`,
  `cacheReadTokens`, `cacheWriteTokens`, `reasoningTokens`;
- `turn`, `step`, `seq` — для группировки по ходу и сессии.

Этого достаточно для расчёта; отдельный запрос к TeamoRouter за каждым
сообщением не нужен.

### Прайс TeamoRouter

`GET /v1/models/pricing` — публичный, без ключа. Для каждой модели доступны:

- `cost.input`, `cost.output`;
- `cost.cached_input` / `cost.cache_read`;
- `cost.cache_creation` (и `cache_creation_1h`, если нужно);
- `context_tier_pricing` — множители при превышении порога токенов;
- `pricing_period`, `pricing_multiplier`, `pricing_timezone`,
  `off_peak_discount` — peak/off-peak;
- `service_tier: "fast"` — отдельная цена у fast-модели.

Берём **`cost`**, а не `list_cost`: это уже дисконтированная цена TeamoRouter.

## Формула

```text
cost =
    uncached_input / 1e6 * price.input
  + cache_read     / 1e6 * price.cache_read
  + cache_write    / 1e6 * price.cache_creation
  + output         / 1e6 * price.output
```

Затем:

1. Применить `context_tier_pricing`, если входной объём превысил порог.
2. Применить peak/off-peak множитель по времени запроса и
   `pricing_timezone` (для TeamoRouter — `Asia/Shanghai`).
3. Округлить для отображения, но хранить больше знаков для суммы.

Важно: `inputTokens` в DSH уже не включает cache read/write. Проверено на
живой сессии: `577 + 173 + 200320 = 201070`, то есть
`totalTokens = inputTokens + outputTokens + cacheReadTokens`. Вычитать кэш из
`inputTokens` не нужно; формула выше использует `input`, `cache_read`,
`cache_creation` и `output` напрямую.

## Дневные и месячные затраты

Это **фактические** суммы из billing API, а не оценка:

- `GET /v1/billing/costs?start_time=...&end_time=...` — сумма и число запросов;
- `GET /v1/usage?start_time=...&end_time=...` — токены за тот же период;
- «Сегодня» — с 00:00 локального времени хоста;
- «Этот месяц» — с 1-го числа текущего месяца по текущий момент;
- Host-эндпоинт `/costs` кэширует ответ на 60 секунд;
- UI показывает карточки «Сегодня» и «Этот месяц»: сумма, запросы, токены;
  Host-эндпоинт проверен на живом аккаунте;
- кнопка «Обновить данные» обновляет баланс и обе суммы;
- при ошибке показывается состояние ошибки, а не `$0`.

Фактические суммы не помечаются `≈`; знак `≈` остаётся только у расчётной
стоимости запроса.

## Архитектура

### Host

- Кэш прайса в `plugin/index.js`: `Map<modelId, price>`, TTL 5 минут.
- Проекция сессии `teamorouterCost` через `ctx.sessionProjections`:
  - `apply` складывает `assistant/message` только для провайдеров
    `teamorouter` и `teamorouter-anthropic`;
  - хранит `seq`, `turn`, `step`, `messageId`, `model`, `usage`, `cost`,
    `currency`, `priced` (есть ли цена);
  - `wire.view` отдаёт клиенту:
    - стоимость по `messageId`;
    - сумму по `turn`;
    - сумму по сессии;
    - флаг «нет цены» для неизвестной модели.
- Стоимость считается в момент `apply` по текущему кэшу прайса. Если цена
  модели неизвестна, `cost: null`; UI показывает `—`, а не `$0`.
- При обновлении прайса новые сообщения считаются по новым ценам; уже
  записанные стоимости не пересчитываются. Для первой версии это приемлемо.

### Client

Регистрация через слоты:

1. **Чип у assistant-сообщения** — `conversation.chat.assistant-actions`,
   owner props `messageId`. Компактно: `≈ $0.0042`; tooltip с разбивкой
   input/output/cache.
2. **Строка после хода** — `conversation.chat.turnTail`:
   `≈ $0.012 за ход`; получает `turn`/`seq`, читает сумму проекта.
3. **Итог за сессию** — `conversation.composer.dock`, id
   `teamorouter-cost`, order 2: `≈ $0.042`; обновляется после каждого
   assistant-сообщения.
4. **Строка после хода** — `conversation.chat.turnTail`, id
   `teamorouter-cost`, order 15: сумма хода, число запросов и токены.
   Реализовано в v0.1.3.
5. **Чип у ответа** — `conversation.chat.assistant-actions`, id
   `teamorouter-cost`, order 20: стоимость последнего запроса хода с
   разбивкой по input/output/cache в подсказке. Реализовано в v0.1.3.
   Слот рендерится у финального assistant-сообщения хода, поэтому полная
   стоимость всех шагов хода — в строке `turnTail`.
6. **Сверка с billing API** — клик по чипу сессии в композере. Диалог
   показывает оценку, факт по ключу за период, разницу и число запросов.
   Реализовано в v0.1.4; факт не изолирует сессию.
4. **Компактная строка в карточке провайдера** TeamoRouter на странице
   Models: `Баланс · Сегодня · Месяц`, обновление и «Пополнить».

Форматирование:

- `$0.0001` … `$0.9999` — 4 знака;
- `$1.00` и больше — 2 знака;
- меньше `$0.0001`, но больше нуля — `< $0.0001`;
- неизвестная цена — `—` с подсказкой «нет цены для модели»;
- у оценённой суммы всегда префикс `≈`, у `—` префикса нет;
- если часть запросов без цены, у суммы сессии стоит `*`;
- локаль ru/en, стили — только на токенах темы DSH.

## Точность

Это **оценка**, а не счёт:

- цены TeamoRouter меняются в реальном времени;
- peak/off-peak и контекстные тарифы;
- fast mode стоит дороже;
- округление и резерв максимальной стоимости на длинном контексте;
- фактические списания видны в billing API. Сверка в плагине показывает
  сумму по ключу за период сессии, а не изолированную стоимость сессии.

Для сверки можно показывать фактическую сумму за сессию через
`GET /v1/billing/costs` (агрегат), но не за конкретный запрос.

**Точная стоимость за конкретный запрос** требует `request_id` из
`GET /v1/billing/requests/{request_id}`. Штатный OpenAI-адаптер DSH не отдаёт
плагину HTTP-заголовки ответа, поэтому это возможно только через свой
адаптер/прокси — отдельный этап, не входит в v1.

## Критерии готовности

- Дневные и месячные суммы видны и обновляются по кнопке.
- Фактические суммы не помечены `≈`, оценка запроса — помечена.
- После каждого ответа TeamoRouter видна оценка стоимости.
- Стоимость хода и итог за сессию сходятся с суммой сообщений.
- Для моделей без цены показывается `—`, а не ноль.
- Другие провайдеры не получают строки затрат TeamoRouter.
- Стоимость не ломает сессию при отсутствии прайса или ошибке сети.
- Оценка помечена `≈`; фактическое списание не выдаётся за неё.

## Открытые вопросы

| Вопрос | Текущее поведение | Что решить |
|---|---|---|
| Дневные/месячные карточки | Показываются всегда | Оставить или сворачивать |
| Стоимость у сообщений | Финальный запрос хода + сумма хода | Нужен ли чип у каждого шага |
| Провайдеры | Только TeamoRouter | Оставить так или расширять |
| Знаки после запятой | 4 до `$1`, 2 от `$1` | 4 или 6 |
| Peak/off-peak и fast mode | Не применяются | Подтвердить семантику |
| Этап 2: точная стоимость | Не начат | Нужен ли адаптер/прокси для `x-request-id` |
