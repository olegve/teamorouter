# Аккаунт TeamoRouter

Документ описывает всё, что связано с учётной записью и балансом TeamoRouter
в DeepSeek Harness: API, ограничения штатной страницы «Аккаунт», варианты
размещения UI и план реализации.

## Требование

В настройках DSH должна быть отдельная страница «TeamoRouter»,
которая позволяет:

1. вставить API-ключ и одной кнопкой подключить аккаунт;
2. сразу создать провайдера TeamoRouter и импортировать модели;
3. видеть баланс аккаунта;
4. обновлять баланс и модели без перезапуска DSH.

Штатную страницу «Аккаунт» DeepSeek не трогаем: у неё нет слота расширения,
поэтому наша страница — отдельная секция настроек.

## API TeamoRouter

Базовый URL: `https://api.teamorouter.com/v1`.
Авторизация: `Authorization: Bearer sk-teamo-...`.
Ключ идентифицирует аккаунт; отдельного `account_id` в запросах нет.

| Метод | Назначение |
|---|---|
| `GET /v1/models` | Список моделей, доступных ключу (нужен ключ) |
| `GET /v1/models/pricing` | Публичный каталог с ценами и метаданными моделей |
| `GET /v1/billing/balance` | Текущий баланс |
| `GET /v1/billing/costs?start_time=...&end_time=...` | Траты за период |
| `GET /v1/usage?start_time=...&end_time=...` | Токены за период |

`GET /v1/models` проверяет ключ и возвращает доступный набор моделей;
`GET /v1/models/pricing` не требует ключа и даёт `context_window`,
`max_output_tokens`, `billing_mode`, `owned_by` и цены. Для импорта моделей
используем пересечение двух ответов: авторизованный список + публичные
метаданные.

Период задаётся Unix-временем в секундах, диапазон — не больше 90 дней.
Ответ баланса:

```json
{
  "balance": {
    "value": "85.320000",
    "currency": "USD"
  }
}
```

Ответ трат:

```json
{
  "start_time": 1784044800,
  "end_time": 1784131200,
  "total_amount": { "value": "1.280000", "currency": "USD" },
  "requests": 86
}
```

Ошибки: `401` — ключ отсутствует/неверен, `404` — запись не найдена,
`429` — rate limit, `5xx` — временная ошибка. При ошибке нельзя показывать
баланс `0` — нужно отдельное состояние «не удалось получить баланс» с retry.

Примечание: в документации TeamoRouter примеры billing используют
`https://teamorouter.com`, но `https://api.teamorouter.com` отвечает так же.
Для единообразия с провайдером используем API-хост.

## Штатная страница «Аккаунт» в DSH

Страница «Аккаунт» — это **одна ячейка** list-слота `settings.section` с
`id: "account"`. Её регистрирует пакет
`@deepseek-ai/dsh-client-ui-settings-account` компонентом `AccountSection`.

Что проверено:

- в живом дереве слотов `settings.account` отсутствует;
- у `settings.section` есть только дочерние `settings.general.item`,
  `settings.plugins.tab`, `settings.models.provider-card`,
  `settings.models.footer` — внутри «Аккаунта» дочерних слотов нет;
- плагин аккаунта регистрирует только `settings.section` (`AccountSection`),
  `settings.launcher` (`AccountMenu`), `settings.models.sign-in`,
  `shell.quota-notice` и `shell.overlay`;
- секция «Аккаунт» регистрируется только при сохранённом DeepSeek-credential,
  то есть у пользователя без DeepSeek-логина её вообще нет.

Следствия:

- **Добавить блок внутрь существующей страницы нельзя** — там нет слота.
- Регистрация своего `settings.section` с `id: "account"` **заменяет**
  страницу, а не дополняет её (list-слот с ключом `id`).
- Оригинальный `AccountSection` не экспортируется из пакета, поэтому обернуть
  его и добавить свой блок нельзя. Замена означает полную перереализацию
  DeepSeek-логина, профиля, баланса, бонусов и онбординга — не рекомендуется:
  дублирование UI, привязка к внутренностям и поломки при обновлениях.

## Варианты размещения баланса

| Вариант | Оценка |
|---|---|
| Отдельная секция «TeamoRouter» (`settings.section`, `id: "teamorouter-account"`, `order: -9`) | **Рекомендуется** |
| Строка баланса в карточке провайдера TeamoRouter (`settings.models.provider-card`, ключ `llm-pi-ai`, условие `provider.id === 'teamorouter'`) | **Рекомендуется как дополнение** |
| Чип в шапке настроек (`settings.action`) | Возможно, но виден на всех страницах настроек |
| Индикатор в сайдбаре (`sidebar.footer.action` / `sidebar.panellist`) | Возможно, если нужен постоянный доступ |
| Плавающий виджет через `shell.overlay` | Технически возможно, но это не часть страницы; позиционирование хрупкое — не рекомендуется |
| Замена штатной секции `account` | Не рекомендуется (см. выше) |

Штатный «Аккаунт» имеет `order: -10`, «Общие» — `0`. Секция с `order: -9`
встанет сразу под «Аккаунтом» и будет восприниматься как его продолжение.

## Предлагаемый UI

### Подключение в один клик

Страница показывает поле API-ключа и кнопку **«Подключить»**. По нажатию
Host выполняет всю цепочку:

1. проверяет формат ключа (`sk-teamo-...`);
2. вызывает `GET /v1/models` — это и проверка ключа, и список доступных моделей;
3. загружает `GET /v1/models/pricing` для метаданных и фильтрации;
4. отбирает чат-модели: убирает image/midjourney/jev/embedding;
5. сохраняет ключ через `credentials.set` под `TEAMOROUTER_API_KEY`;
6. создаёт/обновляет `llm-pi-ai.providers.teamorouter` (OpenAI Chat Completions)
   и, если включён Claude, `llm-pi-ai.providers.teamorouter-anthropic`
   (Anthropic Messages);
7. запрашивает баланс через `GET /v1/billing/balance` и возвращает результат.

Правила:

- **Существующий `teamorouter` не перезаписывается целиком.** Если провайдер уже
  настроен (как у текущего пользователя), обновляются ключ, `baseURL` и
  `displayName`, а пользовательский список моделей сохраняется. Кнопка
  «Обновить модели» может добавить недостающие модели отдельно.
- **Claude — отдельным маршрутом.** Один custom-провайдер = один протокол,
  поэтому Claude идёт через `anthropic-messages`, остальные — через
  `openai-completions`. Один ключ работает для обоих.
- **`402` — не неверный ключ.** Если ключ валиден, но баланс нулевой,
  подключение считается успешным, а страница показывает предупреждение
  и ссылку «Пополнить».
- **Ключ не остаётся в браузере.** После успешного сохранения поле очищается;
  все дальнейшие запросы баланса идут через Host.
- **Повторное подключение** используется для замены ключа и обновления
  метаданных; оно не создаёт дубликаты провайдеров.

### Страница «TeamoRouter»

- Если ключ ещё не сохранён — форма подключения: поле ключа и кнопка
  «Подключить».
- Если подключено — карточка статуса: баланс, дата обновления, количество
  моделей, кнопки «Обновить данные», «Обновить модели», «Заменить ключ».
- Карточка баланса: сумма в USD, дата/время последнего обновления.
- Карточки «Сегодня» и «Этот месяц»: фактические затраты, число запросов и
  токены через `GET /v1/billing/costs` и `GET /v1/usage`; см.
  [costs.md](costs.md).
- Раскрывающийся список моделей: имя, ID, протокол (OpenAI/Anthropic),
  контекст, vision и reasoning; кнопка «Сделать основной» назначает модель
  по умолчанию.
- Кнопка «Обновить данные» обновляет баланс и обе суммы затрат; список
  моделей обновляется кнопкой «Обновить модели».
- Ссылка «Пополнить»: `https://teamorouter.com/dashboard?buy=1`.
- Состояния: загрузка, ошибка с retry, нет ключа (подсказка, где его задать).
- Локаль: русский и английский; форматирование через локаль DSH.

### Карточка провайдера

Реализовано в v0.1.1: компактная строка внутри карточки TeamoRouter на
странице Models.

- Баланс, «Сегодня» и «Этот месяц» через те же `/balance` и `/costs`.
- Кнопка обновления и ссылка «Пополнить».
- Показывать только для `provider.id === 'teamorouter'` и
  `teamorouter-anthropic`, чтобы не появляться у других pi-ai-провайдеров.

### Обновление

- При открытии страницы/карточки.
- После завершения хода — с троттлингом (например, не чаще одного запроса
  в 30–60 секунд), чтобы не тратить rate limit на каждый шаг.
- После возврата со страницы пополнения.

## Архитектура

- **Host-часть (один bundle с Client-частью)**:
  - BFF-маршруты через `ctx.webServer.register` под префиксом
    `/api/teamorouter/<random-token>`:
    - `GET /status` — настроен ли провайдер, есть ли ключ, баланс;
    - `GET /balance` — баланс;
    - `POST /connect` — проверка ключа, импорт моделей, запись настроек.
  - Маршрут дополнительно проверяет браузерную сессию через
    `ctx.connection.admit(req)`; случайный токен в пути — вторая защита.
  - Токен генерируется при активации плагина и инжектится в страницу через
    `webserver/index-inject` строкой `{ kind: 'global',
    name: '__TEAMOROUTER_ACCOUNT__', value: { base, dashboardURL } }`;
    клиент читает `globalThis.__TEAMOROUTER_ACCOUNT__.base`.
  - Ключ резолвится из профиля `llm-pi-ai.providers.teamorouter.apiKeyEnv`
    (обычно `TEAMOROUTER_API_KEY`) и читается только на Host через
    `ctx.credentials.resolve`.
  - Настройки пишутся точечно через
    `ctx.settings.mutate('llm-pi-ai', ops, revision)`, чтобы не затереть
    остальные providers и сохранить пользовательские модели.
  - HTTP-запросы к TeamoRouter — с таймаутом, обработкой `401`/`402`/`429`/`5xx`,
    без логирования ключа.
- **Почему не свой Remote-сервис**: `@deepseek-ai/dsh-api-remotes` монтирует
  фиксированный набор namespace на этапе сборки; сторонний bundle не может
  добавить туда новый. Поэтому для связи Client → Host используется
  собственный same-origin BFF-маршрут, а не `ctx.remote.*`.
- **Client-часть**:
  - регистрация `settings.section` с `id: "teamorouter-account"` и `order: -9`;
  - запросы только к своему BFF-маршруту; ключ в браузере не хранится;
  - стили — на токенах темы DSH, без литеральных цветов;
  - локаль — русский и английский.
- **Кэш**:
  - баланс — 30–60 секунд на Host;
  - публичный прайс `/v1/models/pricing` — 5 минут;
  - список моделей — при подключении и по кнопке «Обновить модели».

### Почему страница — отдельная секция

Штатная страница «Аккаунт» — одна ячейка `settings.section` с `id: "account"`
и без под-слотов. Свой `id: "account"` заменил бы её, а не дополнил. Поэтому
наша страница регистрируется как отдельная секция с `order: -9` и встаёт сразу
после штатного «Аккаунта».

### Что осталось по аккаунту

Базовая страница принята. Дневные и месячные затраты реализованы в v0.1.1
(см. [costs.md](costs.md)). Из плана остаются только необязательные/следующие
пункты:

- автообновление баланса после хода с троттлингом;
- проверка краевых случаев: неверный ключ, нулевой баланс, `429`, сетевая
  ошибка, существующий провайдер, отсутствие DeepSeek-аккаунта.

### Установка и проверка

1. `plugin_manager` → `install_bundle` с абсолютным путём
   `/Users/ove/AI/TeamoRouter/plugin`.
2. Обновить страницу Web GUI (F5), чтобы Host внедрил
   `__TEAMOROUTER_ACCOUNT__` и клиентский bundle.
3. Открыть Settings → «TeamoRouter».
4. Вставить ключ `sk-teamo-...` и нажать «Подключить».
5. Убедиться, что появились модели TeamoRouter и баланс.

Если страница показывает «Мост к аккаунту ещё недоступен», значит, страница
была открыта до установки плагина — нужно обновить её.

## Критерии готовности

- Вставка ключа и нажатие «Подключить» создают провайдера TeamoRouter,
  импортируют чат-модели и показывают баланс.
- Модели появляются в селекторе без перезапуска DSH.
- Существующий `providers.teamorouter` не затирается: пользовательские модели
  сохраняются.
- Claude при включённой опции идёт отдельным Anthropic-маршрутом.
- Баланс TeamoRouter виден в интерфейсе и обновляется без перезапуска.
- Дневные и месячные затраты видны и обновляются по кнопке.
- Ключ не покидает Host-сторону и не попадает в логи/клиент.
- Ошибка запроса показывает состояние ошибки, а не фиктивный ноль.
- `402` при нулевом балансе не выдаётся за неверный ключ.
- Штатный раздел «Аккаунт» DeepSeek не изменён и не сломан.
- Новая секция не появляется у пользователей без ключа TeamoRouter.
